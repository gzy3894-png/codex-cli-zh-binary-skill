# Codex for TUI 2.4.0 发布说明

Codex for TUI 2.4.0 重构了配置档、模型目录和上下文策略底层。目标是让配置管理从“多层 shell 菜单和复制文件”升级为可恢复、可验证、不会覆盖用户手写 TOML 的事务系统。

## 配置档 V2

- 配置模式改为扁平的增删改查流程，支持新建、选择、编辑、查看、删除、刷新模型目录和上下文/压缩策略；每一层都能返回或退出。
- 配置档使用稳定 ID。编辑原配置会保留同一个 ID；同名新建默认拒绝覆盖；用户取消确认时不会写入任何运行配置。
- 当前 `config.toml`、登录态或模型目录被外部修改后，会显示 `runtime_dirty`，切换或退出前可同步到当前配置、另存为新配置或暂不保存。
- `codex-local` 新增 `profile-show`、`profile-rename`、`profile-delete`、`profile-sync`、`compact-policy`、`config-status` 和 `rollback-v1`。

## 事务、迁移与回滚

- 新增 Python 配置引擎，使用随包 `tomlkit` 解析 TOML，保留用户注释、未知字段和非配置档管理的通用设置。
- 配置写入使用私有文件锁、事务快照、原子替换和崩溃恢复；中途失败会恢复操作前状态。
- 首次进入 V2 配置模式时可无损迁移旧配置档。迁移前创建完整 V1 备份，迁移幂等，必要时可运行 `codex-local rollback-v1` 回到迁移前状态。
- 普通 `codex` 启动仍不会联网更新脚本、刷新模型目录、自动迁移或覆盖用户手写配置。迁移只在用户显式进入配置模式或调用配置命令时发生。

## 动态模型能力

- 第三方 Provider 的 `/models` 只决定可用模型 ID；推理等级、上下文窗口、工具能力和最小客户端版本从 OpenAI Codex 官方模型目录精确合并。
- 支持显式模型映射。未知或改名模型不会模糊猜测能力，而是进入保守模式并允许用户补充映射。
- GPT-5.4、GPT-5.5 和 GPT-5.6 系列按官方目录展示真实窗口；支持模型声明的 `max` / `ultra` 推理等级，不再由 shell 菜单硬编码。
- `codex-context status` 会报告原始、最大和有效上下文窗口、有效窗口比例、自动压缩阈值与来源、当前推理等级。
- 压缩策略支持“跟随模型”和固定 token 阈值。跟随模型时由 Codex 按模型目录计算；迁移旧的固定 `220000` 配置时由用户选择保留或切换。

## 安装与兼容

- 完整安装和显式脚本更新会同步配置引擎、官方模型镜像及随包 Python 依赖。
- 从旧版脚本首次显式进入配置模式时，如果配置引擎资源缺失，会按需补齐；下载或自检失败时不会修改用户配置。
- 最低运行依赖补充 `python3`。API Key 不进入命令行参数、配置引擎 JSON 输出或菜单摘要。

## 验收重点

- 配置档 CRUD、同名保护、取消不写入、注释保留、密钥脱敏和 `runtime_dirty` 同步。
- V1 迁移幂等、迁移崩溃恢复、完整回滚和两种 `220000` 迁移策略。
- GPT-5.4 / GPT-5.5 / GPT-5.6 上下文与 `max` / `ultra` 推理等级。
- Provider 缓存回退、未知模型保守模式和真实 Codex `model_catalog_json` 解析。
- 新安装、旧更新器按需补资源、普通启动不联网不迁移不覆盖配置。

## 版本与回滚

- 版本：`versionName=2.4.0`，`versionCode=55`
- 包名：`com.gzy3894.codexfortui`
- 正式签名证书 SHA-256：`a40da80a59d170caa950cf15c18c454d47a39b26989d8b640ecd745ba71bf5dc`
- APK 只通过 GitHub Actions 构建、签名和发布，不在本地运行 Gradle/APK 构建。

Android 不支持普通覆盖安装降级；从 2.4.0 回到更低 `versionCode` 需要发布更高 `versionCode` 的前滚回滚包，或卸载重装并承担数据迁移/丢失风险。
