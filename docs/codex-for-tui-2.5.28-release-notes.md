# Codex for TUI 2.5.28

2.5.28 更新第三方 Responses API 的模型能力兜底、上下文输入和自动压缩策略。

## 默认策略

Provider `/models` 通常只返回模型 ID，不能可靠提供上下文与推理能力。新版按以下规则生成第三方 `model_catalog_json`：

- 精确匹配或显式映射到随包官方目录的模型，保留其真实上下文、默认推理等级和全部官方档位。
- 无法识别的模型使用 `272000` token 上下文。
- 第三方模型默认在上下文的 80% 自动压缩；未知模型默认阈值为 `217600` token。
- 未知模型提供 `low`、`medium`、`high`、`xhigh` 四档基础推理，默认 `medium`。
- `max`、`ultra` 等额外档位只对官方目录明确声明支持的模型展示。

这套兜底替代了“上下文、压缩阈值和推理等级全部为空”的旧行为，避免未知模型把 Skill 元数据预算降级为固定 8000 字符。

## 配置交互

新建第三方配置或重新选择模型后，配置模式会增加“上下文长度”输入：

- 已识别模型默认显示目录中的真实值。
- 未知模型默认显示 `272000`。
- 用户可以直接回车接受，也可以输入服务实际支持的 token 数。
- 保存时自动计算并显示 80% 压缩阈值。

用户输入值按模型写入目录元数据。手动执行 `codex-local refresh-models`、修改 API/Key 或覆盖安装后进行 APK 离线目录重建时，已有覆盖值不会丢失。

全站固定 token 策略仍然保留。用户显式选择固定策略后，根配置中的固定阈值优先于目录的 80% 跟随模型阈值。

## 升级

直接覆盖安装 2.5.28 APK 并重新打开 App：

- 不要卸载旧 App。
- 不要清除 App 数据。
- 不需要手动运行 `codex 更新` 或 `codex-local refresh-models`。
- 已有第三方配置会在 APK 升级事务中离线重建并应用新默认策略。

普通启动仍不会联网刷新 `/models`，也不会覆盖用户手写的通用 TOML 配置。

## 回归覆盖

- 未知模型 272k 上下文、80% 压缩和四档基础推理。
- 已识别模型保留 `max/ultra` 等官方额外档位。
- 用户输入上下文后按 80% 计算阈值。
- 上下文覆盖值跨配置更新、模型刷新和 APK 升级重建保留。
- 生成目录可由随包 Codex `0.144.1` 真实解析。
